3. Cloudflare bot protection

On both websites Cloudflare sets the cookie __cf_bm to recognise automated access (bots). It holds an identifier that Cloudflare derives from properties of the connection and expires after 30 minutes. If a request looks suspicious, Cloudflare may show a check page instead of the page. A Cloudflare script runs in your browser there and evaluates technical properties of your browser and device; after a passed check Cloudflare sets the cookie cf_clearance, which by default expires after 30 minutes. Cloudflare does not insert a script into the normal pages.

Legal basis: Art. 6(1)(f) GDPR; my legitimate interest is protecting the websites against misuse. Accessing your device for this is strictly necessary (§ 25(2) no. 2 TDDDG).

7. Chat assistant

On every page of kabine.dev you can open a chat at the bottom right that answers questions about Kabine. An AI writes the answers from Kabine's documentation; they can be wrong. Please don't enter personal data in the chat. As long as you don't send a message, nothing is transmitted or stored. Without JavaScript the chat does not appear.

7.1 What happens to your message

Your message goes over HTTPS to this website's server (a Cloudflare Worker), in the body of the request, not in the address. The server first checks it with a decision model (Clef-flash): whether it is about Kabine, whether it contains personal data and whether it tries to manipulate the assistant. Greetings, thanks, messages unrelated to Kabine and manipulation attempts get a fixed reply, without another model. Questions about Kabine then go to a second decision model (Clef), which picks matching sections of the documentation, and to a language model (GLM-5.3), which writes the answer. The models get your message and, as context, the last two questions and answers of your chat, never a message recognised as a manipulation attempt. Under each answer the chat shows which route it took.

The chat refuses messages with personal data. The server itself recognises obvious e-mail addresses, phone numbers and account numbers (IBAN); such messages go to no model. Clef-flash recognises names, postal addresses, dates of birth and similar details. In both cases you get a fixed reply asking you to ask again without these details. The message goes to no language model and is not stored, not even in your chat's history; only its time is kept for the rate limit. The detection is not perfect, so please don't enter personal data in the first place.

All models run on Cloudflare Workers AI, as a processor as described in section 2; the makers of the models receive nothing. Cloudflare does not keep Workers AI inputs and outputs beyond processing the request and does not use them to train AI models; it keeps only operational data without content (such as model, time, number of tokens, duration). The requests go through Cloudflare's AI Gateway. With every request the server tells it not to create a log entry and not to cache anything; it only counts calls, tokens and costs, without content. The server itself writes no logs (Workers Logs are switched off): no messages, no chat id, no error messages.

8. Demo on handball.kabine.dev

The demo shows the app with an invented club. You use it without signing up, through shared demo access (player, parent, coach, admin) that all visitors use together. Whatever you enter there is seen by other visitors. Please do not enter real personal data. Email, SMS, passkeys, profile pictures, uploading a club logo, feedback and the game schedules from handball4all are switched off in the demo.

Every night at 3:00 (German time) the demo is reset: everything visitors entered is deleted on the server and the invented club is created again.

Legal basis: Art. 6(1)(f) GDPR; my legitimate interest is presenting the software and letting people try it. Accessing your device (section 8.1) is strictly necessary for the demo to work the way you use it (§ 25(2) no. 2 TDDDG).
