# Tasks from the original club app

Kabine started as the app of one handball club, which is still developed on its own. New features and bug fixes made there are listed here so they can be brought into Kabine. Whoever works on Kabine takes an open entry, ports it the Kabine way (English source, Lingui, club profile instead of club data, modules, tests) and moves it to "Done" with the Kabine commit.

Entries describe the change, not the club: no names, domains or data of the club.

Format per entry: date, title, what changed and why, where in the code (file and function names are the same in both code bases unless noted), and anything that needs adapting for Kabine.

## Open

- **2026-10-19 Coaches, group leads and organizers can say "I'm not there".** Coaches wanted to tell team and co-coaches that they miss an event without cancelling it. Leaders are not participants: no yes/no, no reminders, no counts, stats, squad or "unexcused". New table `leader_absences (event_id, person_id, note, team_informed, created_at, PK(event_id, person_id))`, no row = present. Who: coaches of the event's teams (role on the actor, so admin views without coach rights cannot), leads of a group, creator and organizers of a special event; club-wide events have none. Only for oneself, only before start, not for cancelled events. `PUT /events/:id/absence {note?, informTeam?}` and `DELETE /events/:id/absence`. Event detail gets `leaders: LeaderEntry[] {personId, name "First L.", role coach|lead|organizer, absent, note, canChange}`: coaches/admins see all leaders with note; everyone else who can see the event sees only absent leaders (and themselves), never the note, regardless of "responses visible to all" (the switch protects kids from a domino effect among peers; a missing coach is organisation the team needs). Summary gets `leaderAbsent` (badge "You're not there" in list and next card). Push: other leaders always with note (topic coach); participants and parents in charge only with `informTeam`, without note (topic events); undo sends "is there after all" to the same people; editing the note sends nothing. If no coach/lead is left, the event page suggests cancelling for everyone or sorting out a stand-in in the chat; the cancel confirmation points to "I'm not there". Code: TVK `migrations/0023_leader_absences.sql`, `worker/domain/leaders.ts`, `worker/routes/events.ts` (absence routes, event detail), `worker/domain/events.ts` (`ctx.leaderAbsent`), `src/pages/event.tsx` (`Leaders`, `AbsenceSheet`), `src/pages/home.tsx`, `test/leader-absence.test.ts`, e2e "Trainer meldet sich für ein Training ab". Kabine: Kabine is public and clubs may already run it, so the schema change is a **new timestamped migration file** (`YYYYMMDDHHMM_core_leader-absences.sql`), not an edit of `0001_init.sql`. Include the `staff` role as a leader too if that fits Kabine's staff semantics. Add the table to the export list and to `docs/privacy.md` (free-text note, visible to coaches/admins only). Texts through Lingui with German translation.

- **2026-10-19 Record attendance after an event: present, excused, unexcused.** Replaces the "missed without excuse" switch. After start, coaches set per participant "Present", "Excused" (e.g. told the coach but forgot to decline in the app) or "Unexcused"; also "declined but came anyway". The player's own yes/no stays unchanged, the coach's entry wins. New table `attendance_marks (event_id, person_id, status present|excused|unexcused, marked_by, marked_at, PK(event_id, person_id))`. Without an entry: yes = present, no/standing/inactive = excused, no answer stays open (listed first as "Still to record"). An entry equal to that default is not stored. Optional participants only "Present"/"Not there", never unexcused; unexcused only without a decline. Window: coaches until the end of the day after the event (local time), admins (not in coach mode) the whole season; detail gets `attendanceUntil` and `attendanceEditable`. The attendance protocol follows (present -> present, excused -> declined, unexcused -> unexcused; an optional participant marked present gets a row; a late decline does not count as late if the person came). Players and parents see their own entry ("Was there", "Excused", "Unexcused"); no push. Endpoint `PUT /events/:id/attendance/:personId {mark: present|excused|unexcused|null}`; the old `PUT /events/:id/unexcused/:personId` stays for cached app versions. Coach view of a past event: tiles present/excused/unexcused/open and a segmented control per row with what the player had said. Code: TVK `migrations/0024_attendance_marks.sql`, `worker/routes/events.ts` (`setAttendance`, `defaultMark`), `worker/domain/attendance.ts` (`attendanceStatus`, `attendanceSync`), `worker/domain/events.ts` (`ctx.marks`, `attendanceUntil`), `src/pages/event.tsx` (`AttendanceList`), `src/respond.tsx` (`AttendanceBadge`), `test/attendance-marks.test.ts` (including a migration test). Kabine: **new timestamped migration** (`YYYYMMDDHHMM_core_attendance-marks.sql`) that creates `attendance_marks`, copies every row of `unexcused_absences` as `unexcused` (keep `marked_by`, `marked_at`) and only then drops the old table, so clubs keep their marks; test it like TVK's migration test (apply all older migrations, insert, apply the new one). Update the export list, the team page count (`status = 'unexcused'`), FAQ and Lingui texts.

- **2026-10-19 Invitation links are for setup only; "Straight to the app" when opened again.** Parents kept opening the team's parent link instead of the app and then found their child greyed out. Three changes, all in the app: (1) The parent link's share text (`inviteMessage` in `src/pages/team.tsx`) gets a line after the install hint: "You only need the link once to set up. From then on, open the app from the icon on the home screen." (2) `src/pages/join.tsx`: a shared text `ONCE` ("You only need this link once. From then on, open the app from the icon on the home screen or at <host>.", host from `location.host`) appears under the form for people who are not signed in, and as a muted second paragraph on the "Done" screen after joining through a team link or linking a child (`Done` gets an optional `note`, `finish(text, note)`). (3) A parent who is already signed in and opens the parent link again sees a box (region "Already in the app"): "You are signed in as <name> and already in the app. <Child> is already linked to you. <ONCE>" with a primary button "Straight to the app" (route `/`). Below it the child list is headed "Link another child, e.g. a sibling", and the "Link child" button becomes secondary. E2e test "Elternlink: einmal einrichten, beim erneuten Öffnen direkt zur App". Kabine: texts through Lingui with German translation; check the player link text too.
