# Tasks from the original club app

Kabine started as the app of one handball club, which is still developed on its own. New features and bug fixes made there are listed here so they can be brought into Kabine. Whoever works on Kabine takes an open entry, ports it the Kabine way (English source, Lingui, club profile instead of club data, modules, tests) and moves it to "Done" with the Kabine commit.

Entries describe the change, not the club: no names, domains or data of the club.

Format per entry: date, title, what changed and why, where in the code (file and function names are the same in both code bases unless noted), and anything that needs adapting for Kabine.

## Open

Only what players and parents notice; coach and admin functions are left out to keep it short. Static list in code (`CHANGES` in `src/pages/changelog.tsx`), linked as the first row of the help page; the club app's agent rule adds an entry with every user-visible change. - **2026-11-15 "Manage duties": entries show the block time.** In the entries list of `ManageSheet` (`src/pages/helpers.tsx`) each entry now reads "duty · 08:30–11:00 · for ‹child›" (`blockTime`), so entries of two shifts of the same duty can be told apart.
- **2026-11-16 Helpers tab: club events in the unfiltered view.** Without a chip selected, the helpers tab now also loads `/duties/club` and merges club events into the list of the own teams (sorted by start); the "Club" chip shows as active too and tapping it still filters to club events only. - **2026-11-15 "Work as admin" switch also for admins who are parents.** The profile switch (`accounts.coach_mode`) was only offered to admins with a coach role. Admins who are only parents now get it too; switched off they see the app like other parents. Conditions in `loadActor` (`worker/auth/actor.ts`: coach role or a guardianship, otherwise the stored mode is ignored so nobody locks themselves out), `adminSwitch` in the session payload and `PUT /profile/admin-mode` (`worker/routes/auth.ts`); help text `adminMode`.
- **2026-11-15 Delete a duty time block even with entries, after confirmation.** The trash button in "Manage duties" was disabled for blocks with entries, with only a `title` tooltip that never shows on phones, so it looked broken. `DELETE /duties/blocks/:id` now deletes the block's entries with it (no notification, same as removing a single entry; notifies the referee hub if referee entries go). - **2026-11-15 Special events: "Manage helper duties" on the event page.** The event page button "Helpers: add time block" (one block only, then the user had to go to the helper tab) is replaced by "Manage helper duties", which opens the same manage sheet as the helper tab right on the event page (add blocks, apply a template, edit, assign people); with no blocks yet it starts with "add time block" and returns to the sheet so organizers add all blocks in a row. - **2026-11-15 One-time push prompt.** Many parents never enabled push and never opened their profile. Instead of the home card (shown only in the installed app, dismissible), the home screen now opens a sheet "Turn on notifications?" once per device about 1.5 s after start, when push is supported, not denied and the device has no subscription (also "granted but not subscribed"), and the server has a VAPID key; not in admin view modes. Its button calls the system permission prompt directly (browsers require a tap) and subscribes; "Later" or closing never asks again on that device (localStorage `tvk-push-asked`, a new key so people who dismissed the old card are asked once). iPhone browser tabs cannot do push, the install hint covers that. Shared helpers in `src/push.ts` (`pushSupported`, `pushHandled`, `enablePush`), used by the profile too; `PushPrompt` in `src/howto.tsx`. - **2026-11-15 "Helpers from" moves from the duty type to template lines and blocks; rotation.** Admins were copying duty types ("Stewards W", "Stewards M") only to vary which teams help. Now the duty type describes what (name, mode, note, skills, adults only, assigned by coach, "who helps" relative to the event's team, which may be empty), and each template line and block says where helpers come from: default ("who helps"), specific teams (only players of those teams, children via parents; the type's "who helps" does not apply to that block, managers can still sign up), or rotate (templates only): each game, in start order, gets the next team of the list after the one used on the last block of this type with the same list; the assignment is stored (moved/cancelled/new games do not reshuffle) and coaches/admins can change it per game (only within the list). Managers see a hint when the assigned team has its own event at that time (no auto-skip). One week before, the assigned team gets a system message in its chat (once per assignment, again after a change); no push to all parents, and if slots stay open, coaches/admins get the existing open-slots notification and assign people. "Help out" list and "helpers wanted" use the block's teams (rotate: only when it is your team's turn). Admins can merge duty types (template lines, blocks, entries, skills and grants move; source deleted). Migration `0035_duty_sources.sql` adds `helper_mode`/`helper_teams` (JSON list) to `duty_template_items` and `event_duties`, `rotate_team_id`/`rotate_notified` to `event_duties`, and copies the old per-type teams to their template lines and blocks; `duty_type_teams` stays for rollback and is no longer read. Code: `HelperSource`, `helperSource`, `helperTeamsOf`, `blockRoles`, `teamRolesFor(actor, type, teamIds)`, `nextRotationTeam`, `whoSql(..., source)` in `worker/domain/duties.ts`; `rotationConflicts`, `GET /duties/team-options`, `POST /admin/duty-types/:id/merge`, `PATCH /duties/blocks/:id` (`rotateTeamId`, `helperMode`) in `worker/routes/duties.ts`; `rotationNotices` in `worker/domain/duty-notify.ts`; `HelperSourceField` in `src/duty-blocks.tsx`. Tests: `test/duty-sources.test.ts`. This supersedes the per-type "teams" part of the 2026-11-12 entry; port both together.

Everyone sees all duties; signing up follows each duty type's "who helps" across all teams (no groups): parents for children in teams with parents, players of teams without parents count as "parents" themselves (as for team events), players, coaches, members, plus the duty type's picked teams (e.g. ball runners from under-11 and under-13). - **2026-11-12 Helpers from other teams ("help out") and a switch for "helpers wanted".** At adult games, youth teams help out (e.g. floor wipers from under-11 and under-13 teams), other adults as stewards. "Who helps" gets "Teams" with a second step to pick single teams (`duty_type_teams`, migration `0032_duty_teams.sql`), combinable with parents/players/coaches/members. The player of a picked team does the duty at any event where it appears; for children with involved parents a parent signs the child up ("Who helps?"), the entry then names the child (as for youth referees), children with their own account sign up themselves (`teamRolesFor`, `mergeRoles` in `worker/domain/duties.ts`; `HelperRole.doer`). With "assigned by the coach" the picker includes players of the picked teams; an assigned child is linked as child so parents see, get notified and can remove it. New switch on every duty type "Send ‘helpers wanted’" (`duty_types.notify_open`, on for existing types): decided on the duty type, not the template, because one duty is in several templates and manual blocks have none; it covers all possible helpers incl. other teams (`teamHelperAccounts` in `worker/domain/duty-notify.ts`). No birth year counts as adult (mostly parents and coaches). With "parents" the parent counts, not the child; when a parent signs up their child via "Teams", the child counts (`adultRoles`, `adultSql`, `rolesForActor` in `worker/domain/duties.ts`; the actor carries its own and its children's birth years). No new personal data, only the existing birth year. Tests in `test/duties.test.ts` ("Helfer aus anderen Mannschaften", incl. "Nur Erwachsene"), `test/duty-notify.test.ts`, `test/visibility.test.ts`. In Kabine: duties module, texts via Lingui, the export omits the new table/columns until then.

- **2026-11-12 Duty types the coach assigns.** Some duties nobody should pick themselves; the coach assigns them (e.g. for adult teams). New switch on the duty type, "Assigned by the coach" (`duty_types.assign_only`, migration `0031_duty_assign_only.sql`), independent of "needs prior knowledge" (where an admin approves people who then sign up themselves). Nobody signs up themselves (`rolesFor` returns no role unless the person manages the team; `POST /duties` answers 403 `assign_only`); the helper tab shows "assigned by the coach" on free slots. Coaches, admins and organisers assign through "enter someone", and "who helps" still applies: the picker (`GET /duties/events/:id/people?type=<id>`) only lists matching people and the server rejects others with 400 `not_in_who` (`whoSql(type, person, teamSet)` in `worker/domain/duties.ts`, same rules as `rolesFor`; for all other duty types "enter someone" stays open to anyone in the club). A name without account stays possible. The assigned person gets a notification right away, "You are assigned: <duty>" with time and who assigned, over the channel of the 3-day reminder (`sendDutyAssigned` in `worker/domain/duty-notify.ts`), and may remove themselves. No "helpers wanted" for these duties, they do not count as "helpers needed"; coaches still get the open-slot reminder. Tests in `test/duties.test.ts` ("Dienst, den der Trainer vergibt") and `test/duty-notify.test.ts`, e2e. In Kabine this belongs to the duties module; texts through Lingui.
